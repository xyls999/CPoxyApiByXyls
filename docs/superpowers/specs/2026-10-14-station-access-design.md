# 内网 AI 中转站：来源验收、入口与赠额设计

## 决策与边界

- 继续使用现有 new-api 登录、注册、会话、令牌和计费实现；不复制身份验证代码，不修改 new-api 的受保护品牌与署名。
- 三来源指 Gemini Web（含已验证的独立 4 Argon 实验实例）、学习通课程 AI、ChatGPT Web。每个未通过网关真实问答的来源保持禁用；监听和模型列表不是成功判据。
- 登录/注册页面沿用 new-api 的现有安全流程，仅对 `AuthLayout` 做站点无关的响应式双栏视觉优化，保留原有 Logo、系统名称、认证表单、法律条款与署名；首页使用官方 `HomePageContent` HTML 模式进行响应式排版，提供登录、注册、在线测试与来源状态入口。静态来源状态只表述“上次验收”，不冒充实时在线。
- “送 10 亿 token”解释为**基准 token 等值赠额**而非固定 token 上限：采用仓库当前基准价每千 token $0.002、`QuotaPerUnit=500000`，注册时赠 `1_000_000_000 / 1000 * 0.002 * 500000 = 1_000_000_000_000` 内部额度。实际可用 token 因所选模型、输入输出价格不同而变化。页面必须注明“等值/非固定 token 数”。沿用服务器侧 `QuotaForNewUser` 赠额，绝不只改前端显示。
- 新建账号会获得高额站内配额；限制 Windows 入站规则为 LocalSubnet，页面说明 HTTP 仅适合可信内网，正式公开运营前必须部署 HTTPS 与注册防滥用。当前缺少 SMTP、Turnstile 凭据，不能假装已启用验证。
- Google 网页登录态只存在本机受限 `.runtime/`/数据库；不能写入网页或仓库。4 Argon 来自上游尚未合并的 PR #37，仅作为标明实验性质的独立回环渠道。

## 数据与交互

- 根页展示可用 Gemini、实验 Argon、学习通等待登录、ChatGPT Web 等待排障；CTA 指向 `/sign-in`、`/sign-up`、`/playground` 和 `/models`。
- 现有注册接口调用 `User.Insert`，从 `QuotaForNewUser` 读取服务器侧赠额；只有真实新账号创建才享有一次。不得将现金、硬 token 上限和内部配额混称。
- 网关入口保持 `http://<本机内网 IP>:3000`；上游 8083/8787/8788/18083 只监听 `127.0.0.1`。来源故障不得在网关中显示为已验证可调用。

## 验收与剩余风险

1. 通过 SQLite 快照上的独立注册测试验证新账号赠额；检查旧账号余额未改、重名注册不会重复赠送。验证 `/api/status` 公告与注册/登录页可访问。
2. 从浏览器检查首页移动与桌面布局、登录注册链接；由服务端读取新 HTML 内容；通过 new-api 真实问答验证当前 Gemini 与 Argon。
3. 学习通需本人完成课程登录并开放机器人后才能问答验收；ChatGPT Web 的 `generation_stuck` 必须取得真实回答。两项在此之前保持 `status=2`。
4. 本设计不声称 HTTPS、完整注册防刷、10 亿 token 硬上限或实验 Argon 长期稳定；需要这些能力时须另行实现并验收。
